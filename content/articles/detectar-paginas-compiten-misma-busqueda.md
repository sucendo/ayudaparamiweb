Cuando una web lleva años publicando, llega un momento en el que el problema ya no es encontrar nuevos temas. El problema es saber si realmente necesitamos otra URL.

Dos artículos pueden parecer distintos porque tienen títulos diferentes y, sin embargo, terminar respondiendo a la misma pregunta. También puede ocurrir lo contrario: dos páginas muy parecidas pueden tener sentido si cada una cubre una intención claramente distinta.

Por eso hablar de **canibalización de contenidos** no debería reducirse a buscar palabras clave repetidas.

La pregunta útil es otra:

**¿qué página debería aparecer cuando alguien busca esta información y qué función cumple cada URL dentro de la web?**

Si no podemos responder con claridad, probablemente tenemos trabajo editorial pendiente.

## El problema no es repetir una palabra clave

Una web puede mencionar muchas veces una misma expresión sin competir consigo misma.

Imagina estas cuatro páginas:

- qué es el rendimiento web;
- cómo medir el rendimiento de una web;
- cómo optimizar imágenes, CSS y JavaScript;
- cómo configurar caché y compresión.

Todas hablan de velocidad y rendimiento.

Eso no significa que sobren tres.

Cada una puede resolver una necesidad distinta.

La competencia interna aparece cuando dos o más URLs **terminan intentando resolver esencialmente la misma intención** y no existe una diferencia clara para el usuario.

Por ejemplo:

- "cómo acelerar mi web";
- "consejos para que una web cargue más rápido";
- "10 formas de mejorar la velocidad de una página".

Si el contenido, el público y el resultado esperado son prácticamente iguales, quizá estamos repartiendo una sola respuesta entre varias URLs.

## Empieza por la intención, no por el título

Los títulos pueden engañar.

Dos páginas con títulos diferentes pueden responder a la misma búsqueda. Y dos títulos casi iguales pueden tener objetivos distintos.

Antes de decidir nada, resume cada URL en una frase.

Por ejemplo:

| URL | Función real |
| --- | --- |
| /que-es-cache-web | Explicar qué es la caché |
| /configurar-cache-web | Enseñar a configurarla |
| /problemas-cache-wordpress | Diagnosticar errores concretos |
| /mejorar-velocidad-web | Visión general del rendimiento |

Si necesitas escribir prácticamente la misma frase para dos URLs, ya tienes una señal.

No significa que debas fusionarlas automáticamente, pero sí que merece la pena revisarlas juntas.

## Search Console puede revelar solapamientos

Una de las formas más útiles de detectar páginas que compiten es observar qué consultas muestran varias URLs de tu sitio.

En el informe de rendimiento de Search Console puedes revisar una consulta y comprobar qué páginas han recibido impresiones o clics para ella.

No busques únicamente cuál tiene más clics.

Fíjate también en:

- qué URL aparece con más frecuencia;
- si Google alterna entre dos páginas;
- si una sube cuando la otra baja;
- si ambas tienen una posición parecida;
- si la consulta encaja realmente con las dos;
- si cada una recibe variaciones distintas de la misma búsqueda.

Un pequeño solapamiento es normal.

El problema aparece cuando varias páginas se reparten de forma persistente las mismas consultas sin una razón clara.

## Alternar posiciones no demuestra por sí solo una canibalización

Es fácil mirar dos URLs que aparecen para una consulta y concluir que una está perjudicando a la otra.

No siempre es así.

Google puede mostrar páginas diferentes según:

- dispositivo;
- ubicación;
- contexto de búsqueda;
- intención concreta;
- frescura;
- tipo de resultado;
- variaciones de la consulta.

Por eso conviene mirar un conjunto de datos, no una captura aislada.

Si una página aparece para una consulta informativa y otra para una variante más transaccional, quizá la separación funciona perfectamente.

La clave es entender **por qué existe cada URL**.

## Compara el contenido real de las páginas

Después de detectar dos candidatas, abre ambas.

No compares solo H1 y title.

Revisa:

- introducción;
- preguntas que responde;
- profundidad;
- ejemplos;
- público objetivo;
- tipo de resultado que promete;
- llamadas a la acción;
- enlaces internos;
- fecha y contexto;
- consultas por las que recibe visibilidad.

Si al leerlas parece que una podría sustituir casi por completo a la otra, la duplicidad es mucho más probable.

Si cada página conduce al usuario por un camino distinto, puede tener sentido mantener ambas.

## Hay cuatro decisiones posibles

Detectar solapamiento no significa que la solución sea siempre fusionar.

Normalmente tendremos cuatro opciones.

### Mantener ambas

Tiene sentido cuando responden a intenciones diferentes.

Por ejemplo:

- una página explica un concepto;
- otra enseña a realizar una tarea;
- una está dirigida a principiantes;
- otra profundiza en un caso avanzado;
- una es informativa;
- otra pertenece a una categoría o servicio.

En este caso conviene reforzar la diferencia.

Revisa títulos, introducciones, H1 y enlazado interno para que cada URL deje claro su papel.

### Reorientar una de ellas

A veces dos artículos nacieron parecidos, pero uno puede evolucionar hacia un tema más específico.

Por ejemplo:

- página A: guía general sobre enlaces internos;
- página B: auditoría de enlaces internos en sitios grandes.

No hace falta eliminar una.

Puede ser mejor redefinir la segunda y profundizar en un problema que la primera no cubre.

### Fusionar

La fusión tiene sentido cuando dos páginas ofrecen prácticamente la misma respuesta y mantener ambas obliga a repartir actualización, enlaces y autoridad.

En ese caso:

1. decide qué URL conservar;
2. reúne en ella lo mejor de ambas;
3. evita copiar fragmentos repetidos sin reorganizar;
4. redirige la URL retirada;
5. actualiza enlaces internos;
6. revisa sitemap y referencias.

La [auditoría de contenidos antes de septiembre](/auditoria-contenidos-antes-de-septiembre) desarrolla con más detalle cómo decidir entre actualizar, fusionar, redirigir o eliminar.

### Eliminar sin sustitución

Es la opción menos frecuente.

Puede tener sentido si la página ya no tiene utilidad, no recibe tráfico relevante, no tiene enlaces valiosos, no forma parte de ningún recorrido y no existe un destino equivalente.

No conviertas una limpieza editorial en una colección de redirecciones irrelevantes.

Redirigir todo a la portada o a una categoría genérica no siempre ayuda.

## Qué URL conviene conservar al fusionar

No elijas automáticamente la más antigua ni la que tenga el título que más te guste.

Compara:

- clics orgánicos;
- impresiones;
- consultas;
- enlaces externos;
- enlaces internos;
- conversiones;
- relevancia de la URL;
- calidad actual del contenido;
- historial y estabilidad.

A veces la página con menos tráfico tiene una URL mejor y un contenido más apropiado para convertirse en la versión definitiva.

En otras ocasiones la decisión es sencilla porque una de las dos ya concentra casi toda la visibilidad.

La URL superviviente debería ser la que tenga más sentido **a largo plazo**, no solo la que haya ganado el último mes.

## Revisa el enlazado interno antes de culpar al contenido

Dos páginas pueden parecer competidoras porque la propia web envía señales confusas.

Imagina que veinte artículos enlazan a una URL antigua con el texto "guía de SEO técnico", mientras que la nueva página, que realmente debería ocupar ese papel, apenas recibe enlaces.

Antes de fusionar, revisa cómo está distribuido el enlazado.

Pregúntate:

- ¿qué página recibe más enlaces internos?;
- ¿con qué anchors?;
- ¿desde qué contenidos?;
- ¿una página importante está casi huérfana?;
- ¿los bloques automáticos enlazan al destino correcto?

La guía de [enlazado interno para SEO](/enlazado-interno-para-seo) puede ayudarte a ordenar estas señales.

## Un cluster no es canibalización

Este punto es especialmente importante.

Una web puede tener diez páginas sobre un mismo tema y estar perfectamente organizada.

Eso es precisamente lo que busca un buen [cluster de contenidos](/clusters-de-contenido-y-seo): una página principal y varias piezas que amplían preguntas diferentes.

Por ejemplo:

**Página principal:** rendimiento web.

**Piezas de apoyo:**

- métricas;
- imágenes;
- JavaScript;
- caché;
- servidor;
- Core Web Vitals.

El problema no es la cercanía temática.

El problema es que dos piezas no tengan una razón distinta para existir.

Una buena prueba consiste en intentar explicar la diferencia sin utilizar palabras técnicas.

Si puedes decir:

> "Esta página explica qué ocurre y esta otra te enseña cómo solucionarlo"

la separación probablemente está justificada.

Si solo puedes decir:

> "Esta dice prácticamente lo mismo, pero con otro título"

hay una señal clara de consolidación.

## Cuidado con las URLs que ya funcionan

Fusionar puede mejorar una arquitectura, pero también puede destruir valor si se hace sin revisar datos.

Antes de retirar una URL comprueba si:

- tiene enlaces externos;
- genera contactos;
- recibe tráfico de una consulta específica;
- aparece en marcadores o documentación;
- recibe enlaces desde campañas;
- tiene una función que no habías detectado.

Una página con poco tráfico no es necesariamente inútil.

Puede resolver una duda muy concreta que conduce a una conversión.

Por eso una auditoría debe combinar SEO, contenido y negocio.

## Después de fusionar, actualiza toda la web

La redirección 301 no debería ser el final del trabajo.

Si eliminas una URL, busca dónde estaba enlazada.

Actualiza:

- enlaces contextuales;
- menús;
- tarjetas relacionadas;
- índices;
- sitemap;
- referencias dentro de otros artículos;
- campañas o documentos que controles.

Una redirección es una red de seguridad.

Cuando puedes modificar el enlace de origen, es mejor apuntar directamente al destino final.

## No esperes resultados al día siguiente

Después de consolidar contenidos, necesitas tiempo para observar qué ocurre.

Guarda una referencia previa:

- clics;
- impresiones;
- consultas;
- posiciones;
- conversiones;
- tráfico total del conjunto.

Después compara el rendimiento de la URL conservada y del tema completo.

Esto enlaza con una idea que ya hemos trabajado en [cómo medir si una mejora web ha funcionado](/medir-si-mejoras-web-han-funcionado): una decisión no se valida porque nos parezca lógica, sino porque el resultado confirma que la web ha quedado mejor.

## Una pequeña matriz ayuda a decidir

Puedes resumir cada caso así:

| Situación | Acción probable |
| --- | --- |
| Misma intención y una URL claramente mejor | Fusionar |
| Misma temática, intención distinta | Mantener |
| Contenido parecido pero ampliable hacia otro problema | Reorientar |
| Página sin función ni valor recuperable | Eliminar |
| Dos URLs útiles pero enlazado confuso | Mantener y reorganizar |
| Una URL antigua recibe señales que debería recibir otra | Revisar enlaces y después decidir |

No es una fórmula automática.

Es una forma de evitar decisiones impulsivas.

## Publicar menos también puede ser una mejora

Cuando una web está empezando, crear contenido nuevo suele aportar oportunidades.

Cuando ya acumula años de publicaciones, el valor puede estar en otra parte: **hacer que cada URL tenga un papel más claro**.

Eso significa que algunas semanas la mejor decisión editorial no será publicar tres artículos nuevos.

Puede ser:

- actualizar uno;
- fusionar dos;
- reforzar enlaces;
- eliminar una página inútil;
- o decidir conscientemente que dos contenidos parecidos deben seguir separados.

Antes de crear una nueva URL, merece la pena hacerse una pregunta sencilla:

**¿esta página va a resolver una necesidad nueva o solo va a repartir entre dos URLs una respuesta que ya tenemos?**

Esa pregunta puede evitar años de contenido redundante.
