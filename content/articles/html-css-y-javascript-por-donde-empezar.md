## Ruta de aprendizaje

### ¿Por dónde empezar de verdad?
Si estás empezando en desarrollo web, lo más importante es entender el orden: primero HTML, después CSS y luego JavaScript. Ese camino te permite construir una base sólida y evitar frustraciones.

HTML define la estructura de la página (títulos, párrafos, listas, imágenes, enlaces). CSS se encarga del diseño visual (colores, espacios, tipografía, diseño responsive). JavaScript añade comportamiento (interacciones, validaciones, contenido dinámico).

Aprender estas tres tecnologías a la vez suele generar confusión. Es mejor avanzar por etapas, con pequeños proyectos reales y objetivos concretos.

## HTML y CSS

### Fase 1: dominar HTML (1 a 2 semanas)
Empieza creando páginas simples: una portada, una página “Sobre mí” y una de contacto. Practica etiquetas semánticas como `<header>`, `<main>`, `<section>` y `<footer>`.

Objetivo de esta fase: construir contenido ordenado y accesible. Si sabes estructurar bien una página sin estilos, ya tienes medio camino hecho.

### Fase 2: aplicar CSS con criterio (2 a 3 semanas)
Cuando tengas estructura, aprende CSS enfocándote en lo esencial: modelo de caja, selectores, tipografía, colores, márgenes, flexbox y grid. No te obsesiones con animaciones avanzadas al principio.

Practica diseño responsive desde el inicio para que tu web se vea bien en móvil y escritorio. La mayoría de visitas suelen llegar desde teléfonos.

## JavaScript

### Fase 3: JavaScript para interactividad (3 a 4 semanas)
Comienza con fundamentos: variables, condicionales, funciones, arrays y objetos. Luego pasa al DOM para manipular elementos de la página y responder a eventos como clic o envío de formularios.

Con eso podrás crear menús desplegables, validación de formularios, pestañas, modales y filtros básicos sin depender de librerías externas.

## Práctica y errores

### Proyectos recomendados para aprender más rápido
- Una landing de negocio local con llamada a la acción.
- Un portafolio personal con sección de proyectos.
- Una lista de tareas (to-do) en JavaScript con almacenamiento local.
- Un formulario de contacto con validación en cliente.

Aprender con proyectos te obliga a resolver problemas reales y te prepara mejor que memorizar teoría.

### Errores frecuentes de principiantes
Uno de los errores más comunes es saltar demasiado pronto a frameworks. React, Vue o Angular son útiles, pero antes necesitas dominar HTML, CSS y JavaScript puro para entender lo que ocurre detrás.

Otro error es copiar código sin comprenderlo. Puedes apoyarte en ejemplos, pero siempre debes modificar, probar y explicar con tus palabras lo que hace cada bloque.

## Plan de estudio

### Ruta de estudio sugerida (90 días)
**Mes 1:** HTML + CSS básico, maquetación y responsive. **Mes 2:** JavaScript básico + DOM + formularios. **Mes 3:** proyectos completos, Git/GitHub y publicación de tu web.

Si estudias 45-60 minutos al día con constancia, al final de ese periodo tendrás nivel suficiente para construir sitios web funcionales y seguir creciendo hacia front-end profesional.

### Conclusión
No necesitas aprender todo a la vez. Necesitas orden, práctica y consistencia. Empieza por lo esencial, construye proyectos pequeños y mejora cada semana.

Con esa metodología, HTML, CSS y JavaScript dejan de ser “tres mundos separados” y se convierten en una sola habilidad práctica para crear webs útiles, rápidas y bien estructuradas.
## Fundamentos técnicos

### Qué aprender de HTML primero
Empieza por texto, enlaces, imágenes, listas, tablas sencillas y formularios. Después incorpora elementos semánticos como `nav`, `article`, `section` y `aside`.

No memorices todas las etiquetas. Aprende a consultar documentación y, sobre todo, a elegir el elemento que mejor describe la función del contenido.

### CSS: domina el modelo de caja
Antes de entrar en diseños complejos, entiende cómo funcionan ancho, alto, padding, borde y margen.

Muchos problemas de maquetación dejan de ser misteriosos cuando sabes calcular el espacio real que ocupa un elemento.

### Flexbox y Grid
Flexbox es muy útil para alinear elementos en una dimensión, como una barra de navegación o una fila de tarjetas. CSS Grid facilita distribuciones de filas y columnas más completas.

Practica ambos con pequeños ejemplos antes de intentar copiar una interfaz grande.

### Responsive desde el comienzo
No construyas primero una web fija de escritorio para adaptarla al final. Prueba el diseño mientras avanzas en distintos anchos.

Utiliza imágenes flexibles, contenedores con límites razonables y media queries cuando el contenido necesite reorganizarse.

## JavaScript y DOM

### JavaScript: entiende el flujo antes del DOM
Practica primero variables, funciones, condiciones y bucles con ejercicios pequeños en la consola.

Cuando esas piezas sean familiares, será más sencillo entender por qué un botón ejecuta una función o cómo un formulario transforma datos.

### DOM y eventos
Aprende a seleccionar un elemento, cambiar texto o clases y escuchar eventos como `click`, `input` o `submit`.

Con estas bases puedes construir pestañas, acordeones, validaciones y pequeñas interacciones sin necesidad de un framework.

## Herramientas y Git

### Usa las herramientas del navegador
La consola, el inspector de elementos y la pestaña de red son parte del aprendizaje.

Cuando algo no funciona, mira primero el error y el HTML generado. Acostumbrarte a depurar desde el principio evita depender de prueba y error.

### Git como siguiente paso natural
Cuando tengas pequeños proyectos, empieza a guardar versiones con Git. No necesitas dominar ramas complejas al principio.

Aprende a crear un repositorio, registrar cambios y volver a un estado anterior. La guía [Git y GitHub para principiantes](/git-y-github-para-principiantes) puede ayudarte.

### Evita copiar proyectos completos
Copiar un ejemplo puede servir para estudiar, pero intenta reconstruirlo después sin mirar y cambia requisitos.

Si una lista de tareas funciona, añade filtros o persistencia. Si una landing está terminada, modifica estructura y estilos para otro negocio.

## Buenas prácticas y frameworks

### Practica accesibilidad desde el inicio
Utiliza etiquetas de formulario, botones reales y encabezados lógicos. Aprender buenos hábitos desde el principio es más fácil que corregirlos después.

Puedes ampliar esta parte con [accesibilidad web: principios básicos](/accesibilidad-web-principios-basicos).

### Cuándo mirar un framework
Cuando seas capaz de construir una interfaz pequeña con HTML, CSS y JavaScript y entiendas cómo se manipula el DOM, podrás valorar mejor qué problema resuelve un framework.

No hay prisa. Una base sólida hace que cualquier tecnología posterior sea más fácil de aprender.

La mejor ruta no es la más rápida, sino la que te permite explicar lo que has construido y modificarlo sin depender de copiar una solución entera.
